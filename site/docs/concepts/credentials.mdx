---
title: Credentials
description: The four kinds, what each one asserts, and what a badge says once it is checked.
---

```c
typedef enum GmKind {
    GM_INDIVIDUAL = 1,
    GM_ORGANIZATION = 2,
    GM_CAPABILITY = 3,
    GM_STAFF = 4
} GmKind;
```

**Individual** and **organization** are badges a root signed directly.

**Capability** is permission for an organization to issue, within a scope.

**Staff** is what an organization issues using that capability.

## What a check gives you

```swift
public struct Badge {
    public let kind: Kind
    public let subject: Subject
    public let category: String
    public let issuedAt: Int64
    public let expiresAt: Int64
    public let issuer: Data
    public let via: Subject?
}
```

`Badge` is built only by a check, never by hand. A credential that hasn't
been through the chain hasn't been checked, and holding this type is the
proof that one has.

`issuer` is the key that signed it: a root for a direct badge, the
organization for a staff one. `via` is the organization a staff badge came
through, which is what a panel reads to say "verified by this organization,
itself verified by us".

## Expiry

```swift
badge.expiresAt  // zero means it does not expire
```

An identity doesn't lapse on its own. Only a staff badge carries a real
expiry, because it certifies a relationship, and relationships end.

## Subjects

```swift
public struct Subject {
    public let chain: UInt64
    public let address: Data
}
```

A wallet-bound identifier, never a handle. A handle is a display name its
owner can change whenever they like, and nothing in the chain depends on one.

## Sizes

```c
size_t gm_preimage_len(void);
size_t gm_signed_len(void);
size_t gm_verified_len(void);
```

Fixed wire lengths, so a host can size a check before it makes one.
