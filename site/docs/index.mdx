gossmark is the engine behind a verified badge. It issues the credentials a
badge is made of and checks them, including the chain behind one: a staff
badge is valid because a key signed it whose power a root key signed.

All of it works offline.

```swift
let badge = try Mark.verifyDirect(signed, roots: roots, revoked: revoked, now: now)
```

## The four kinds

```c
typedef enum GmKind {
    GM_INDIVIDUAL = 1,
    GM_ORGANIZATION = 2,
    GM_CAPABILITY = 3,
    GM_STAFF = 4
} GmKind;
```

An individual and an organization are badges. A capability is permission for
an organization to issue. A staff badge is what an organization issues with
that permission.

## Two things that shape everything here

**Nothing fetches and nothing reads a clock.** A verifier is handed its
roots, its revocation snapshot and the moment to check against. That's what
lets a badge be checked offline, and what makes a client with a wrong clock
fail the same way everywhere.

**Nothing knows what anybody is called.** A credential's subject is a
wallet-bound identifier, so a handle can change without touching a badge.
